## Second increment: distribution reference

`game_store.py` is a Linux host-side reference, not code installed on webOS. The manifest specifies game ID, title, engine, version, ZIP SHA-256, Game.ini entry, and input profile. It stages verified ZIP contents in an isolated directory, rejects traversal, symlinks, reserved paths and case collisions, retains releases, atomically selects a version and provides a separate saves directory. `select` rolls back and `deactivate` hides a game without removing saves. The caller must provide a manifest from the authorized distribution channel and a private library root; this is not signature verification, tamper-proof storage, or power-loss durability. The engine still must be adapted to write saves there instead of in the game directory. `check.sh` runs the reference tests. No private game data is copied.

### Shared listening lifecycle (#53, host preparation)

Operator confirmed seeing the 0.2.4 dry-run message and requested continuous listening until either Voice Edit or L3+R3 toggles it off. Both controls must share one acknowledged desired state, not independently toggle a remote process. The host prototype is a dedicated /aeon/voice route on the existing TLS bridge with explicit aeon.voice scope (no legacy or monitor scope inheritance), server connection nonce, immutable Lantern Gate release identity, launch ID, monotonic sequence and explicit enabled boolean. Duplicate requests are idempotent; conflicting/stale requests and game changes are rejected. A heartbeat every five seconds renews a 15-second lease, with no total duration limit. Stop on connection loss/revocation/game exit, do not automatically start upon reconnection. Client must display actual host acknowledgment, not assume send success. Unknown stop state locks further starts until stopped. Only one microphone owner. No live backend is configured; the default explicitly rejects activation.

Host proof of concept: bwrap unprivileged namespace worked on gway-001 with writable disposable game directory, inaccessible host HOME and separate canary directory, and isolated network. This is not acceptance of the actual Codex voice binary. Its existing helper opens general Codex in HOME and may execute tasks while listening. Next implement the voice/audio service and restricted editor as separate roles, with explicit start/stop acknowledgement and process-owned cleanup, verified isolation of credentials, other repos, saves and runtime. Native client needs authenticated app-specific identity and TLS trust, with an explicitly authorized pairing flow; no borrowing monitor or TV SSAP credentials. Screenshot capture must bind the same launch and release and not capture unrelated screens. No new credential issued, no production bridge change, no microphone activation, no player install. Existing 0.2.4 remains dry-run.
